# ポケモンチャンピオンズ 選出支援ツール

相手のパーティ6体を入力すると、自分のパーティから最適な3体を提案します。

**→ https://ユーザー名.github.io/champions-select/**

- 単一HTMLファイルで完結（外部通信なし・オフライン動作）
- スマホ対応。ブラウザの「ホーム画面に追加」でアプリのように使えます
- ポケモン名はカタカナ / ひらがな / ローマ字で検索できます（例: がぶ / gab）
- 従来方式に加え、純戦略Maximin・厳密な混合戦略Nash均衡・隠れ型ベイズ＋下側CVaRで選出できます
- 強さ測定から、最も苦手な相手6体とその中で最も厳しい3体選出を確認できます
- シーズン1〜5の最終500位以内の構築に対する推定勝率で、パーティと改善案を評価できます
- 改善案では、現在のメガシンカ枠を固定して非メガ枠だけを入れ替えられます

## 数値について

使用率上位100体を1対1で総当たりさせたシミュレーション結果に基づく **選出の目安** です。
交代を含む展開・急所・テラスタルは反映していないため、勝率の予測値ではありません。
使用率や採用率のデータは「バトルデータベース チャンピオンズ」の公開値に基づきます。

## 選出の評価式

自分のポケモン `i` と相手 `j` の対面期待勝率を `P[i][j]`、選んだ3体を `I` とします。

- 対応範囲 `C(I) = mean_j max_{i∈I} P[i][j]`
- 最悪対面 `W(I) = min_j max_{i∈I} P[i][j]`
- 選出の厚み `S(I) = mean_{i∈I,j} P[i][j]`
- 総合評価 `U(I) = 0.5 C(I) + 0.2 W(I) + 0.3 S(I)`

## 選出計算モード

いずれのモードも、メガシンカを2体以上含む3体選出を除外します。
6体から3体の組み合わせは最大20通りなので、双方の選出を比較する利得行列は最大20×20です。

- **既存の総合評価**: 従来どおり、相手6体全体に対する `U(I)` を最大化します
- **純戦略Maximin**: 利得行列 `G[I][J] = U(I; J)` に対して `max_I min_J G[I][J]` を厳密な全探索で求めます
- **混合戦略Nash均衡**: 相手の隠れ型で条件付けした有限ゼロ和ゲームを線形計画法で解き、双方の選出確率・均衡値・LP双対ギャップを表示します
- **隠れ型ベイズ期待値＋下側CVaR**: 相手の持ち物・性格・特性・4技・努力値配分を採用率に従って標本化し、各型での3体選出確率を相手側評価のsoftmaxから推定します。型と選出を結合した各シナリオについて期待値 `E[G]` と、悪い側20%の加重平均 `CVaR_0.20(G)` を求め、`0.75 E[G] + 0.25 CVaR_0.20(G)` を最大化します

相手6体の隠れ型は、各ポケモンの型分布から128組を決定論的な準モンテカルロ法で標本化します。
構築単位の型相関データはないため、6体の型は事前分布では独立と仮定し、型を観測した相手の
softmax選出を通じて型と選出の相関を作ります。
実測の3体選出率はデータに含まれないため、選出確率は相手側の対面評価から得たモデル推定値です。
Nashモードの20×20行列は、各相手選出から推定される隠れ型の事後分布で条件付けした利得の平均です。

相手6体の型を `θ`、相手の3体選出を `J` とすると、共同分布は次のモデルです。

- 型の事前分布: `p(θ) = ∏_j p(θ_j)`
- 型を知る相手の選出: `q(J | θ) = softmax(β U_enemy(J; θ))`
- 型×選出シナリオ: `p(θ, J) = p(θ) q(J | θ)`
- Nash用の事後平均利得: `Ḡ[I,J] = E[G(I,J;θ) | J]`

混合戦略Nashでは、こちらの選出確率を `x` として
`max v  subject to  Σ_I x_I Ḡ[I,J] ≥ v (∀J), Σ_I x_I = 1, x_I ≥ 0`
とその双対問題を線形計画法で解きます。したがって、Nash計算自体には反復近似誤差がなく、
表示する双対ギャップは浮動小数点演算上の残差です。

また「パーティの強さを測定」で表示する最も厳しい相手3体は、相手が `U` を最小化し、
こちらが応戦する3体で `U` を最大化する `min（相手選出）–max（こちらの応戦）` の全探索で求めます。

### 計算実装

選出計算は、設定値・合法選出・対面プロファイル・通常評価を1つのゲームモデルにまとめています。
`U` の計算式は全モードと苦手選出分析で共有しています。通常・Maximinは従来の対面平均行列を使い、
Nash・ベイズでは平均前の型別対面結果から共通のベイズゲームを遅延生成して再利用します。
Nash均衡は、正の利得行列に変換した主問題と双対問題を単体法で解き、双方の混合戦略を求めます。

## 上位構築ベンチマークと改善案

[バトルデータベース チャンピオンズの構築記事検索](https://champs.pokedb.tokyo/article/search?rule=0&season_start=1&season_end=5&type%5B%5D=0&type%5B%5D=1&type%5B%5D=2&type%5B%5D=3&type%5B%5D=9&sort=default&per_page=30)から、
2026-09-07時点でシーズン1〜5の最終500位以内にある691構築を収録しています。
このうち内蔵データで6体とメガ形態を再現できる607構築を計算に使用します。

構築 `b` に対する推定勝率は、双方の合法な3体選出から作る利得行列に対する純戦略Maximin値
`V_b = max_I min_J G_b[I][J]` です。メガリザードンX/Yなどの別形態も区別します。
集計時は各シーズンの重みを等しくし、同じシーズン内では `1 / sqrt(最終順位)` で順位を重み付けします。
パーティの対構築総合値は、順位加重平均75%と下側20% CVaR 25%の合成値です。

改善案は次の二段階で計算します。

1. 全入れ替え候補を、個別対面と各シーズン上位25構築への軽量な代理指標で絞り込みます。
2. 有力候補だけを、再現可能な最終500位以内の全607構築に対するMaximin値で再評価します。

最終結果は「面を広げる」「厚みを足す」「上位構築に勝つ」の3目的に分けて表示します。
持ち物重複やメガシンカ3体以上になる入れ替えは候補から除外します。
